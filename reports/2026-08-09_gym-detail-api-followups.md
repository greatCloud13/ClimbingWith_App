# 백엔드 요청사항 보고서 — 암장 상세 API(`GET /api/gym/{id}`) 연동 후속

- **작성일**: 2026-08-09
- **작성자**: Claude (앱 개발)
- **배경**: 제공해주신 `GET /api/gym/{id}` 실제 연동 완료. 연동하면서 확인된 CORS 이슈와, 기존 화면 스펙 중 이 API로는 채울 수 없는 항목을 정리.

## 1. CORS — 해결됨 (포트 3000으로 통일)

- 백엔드 CORS가 `localhost:3000` origin만 허용하도록 설정되어 있었던 것으로 확인. 저희 웹 프리뷰 포트를 8765 → 3000으로 맞춰서 해결했습니다 (`.claude/launch.json`).
- 모바일(Android/iOS) 빌드에는 원래 해당 없는 이슈였습니다 (CORS는 브라우저 전용 정책).

## 2. 이 API로 채워지지 않는 기존 화면 항목

암장 상세 화면(`/gym/:id`)에 이미 있던 아래 항목은 `GET /api/gym/{id}` 응답에 없어서, 데이터가 없을 때는 해당 UI를 숨기도록 클라이언트에서 처리해뒀습니다 (실제 암장에 가짜 목업 가격/난이도를 보여주면 안 되므로).

- **이용권(가격)**: `pricePlans` 대응 필드 없음 → "가격보기" 버튼이 아예 안 보임
- **난이도 체계(볼더/리드 색 스트립)**: 대응 필드 없음 → "난이도 정보가 아직 등록되지 않았어요" 텍스트로 대체
- **섹터별 담당 종목(볼더/리드)**: `sectorList[].discipline` 같은 필드가 없어서, 클라이언트가 암장의 `gymType`으로 임시 추정 중 (BOULDER/LEAD 암장은 모든 섹터를 그걸로 간주, **BOTH 암장은 일단 boulder로 가정** — 부정확할 수 있음). BOTH 타입 암장의 섹터별 실제 종목 필드가 있으면 정확해집니다.
- **섹터 안 문제(루트) 목록**: `sectorList[].problemCount`(개수)만 있고 실제 문제 리스트가 없음 — 이전 보고서(2026-08-08)에서 요청한 `GET /api/gyms/{id}/sectors/{sectorId}/problems` 그대로 필요합니다.

## 3. `/gym` 탭(암장 목록)은 아직 전부 목업

지금 연동한 건 상세 화면 하나(`GET /api/gym/{id}`)뿐이고, 목록 화면(`/gym` 탭에서 보여주는 암장 카드 리스트)은 여전히 가짜 데이터 3건입니다. 목록 조회 API(예: `GET /api/gyms` — 전체 또는 검색/필터 포함)가 있으면 알려주세요. 홈 화면의 즐겨찾기 목록(`GET /api/home`)과는 별개로, "즐겨찾기 안 한 암장까지 포함한 전체 목록"이 필요합니다.

## 4. 참고 — 응답에서 확인했지만 아직 화면에 안 쓰는 필드

- `isActive`(운영 여부), `memo`(암장 메모) — 현재 화면 스펙에 없어서 파싱만 하지 않고 무시 중입니다. 나중에 "휴업중" 배지나 소개글 등으로 쓸 수 있을 것 같으면 알려주세요.
- `weekendOpenAt`/`weekendCloseAt`가 평일 시간보다 이상한 값(예: 노루 클라이밍의 주말 마감 07:00)으로 오는 경우가 있어 보이는데, 데이터 확인 부탁드립니다 (표시는 받은 그대로 하고 있습니다).

## 5. 게시판으로 확장 — `GET /api/post/gym/{gymId}/posttype/{postType}` 연동 완료

- "공지사항" 버튼을 "게시판"으로 확장: 처음 진입 시 전체 게시글, 상단 태그(전체/공지사항/세팅 일정/분실물 안내/암장 이벤트)로 서버 필터링 조회.
- 경로가 `postType`이 아니라 소문자 `posttype`인 것 확인 (Swagger에 나온 그대로 사용 중). `SETTING_SCHEDULE` 철자도 확인 완료 (메시지에 `SETTING_SCHEDULT`로 적어주셨던 건 오타로 보고 정정해서 반영함 — 다르다면 알려주세요).
- 게시글 탭 시 상세 화면으로 이동은 되지만, 본문(body) API가 아직 없어 안내 문구로 대체됩니다 (2026-08-08 보고서에서 요청한 것과 동일 — `postId`로 본문 조회하는 API 부탁드립니다).

## 6. 즐겨찾기 별 표시 — 임시 방편

- "즐겨찾기가 이미 되어있는데 별이 안 채워져 있다"는 제보를 받아, 홈 화면 즐겨찾기 목록(`GET /api/home`)에 이 암장이 포함되어 있으면 별을 채워서 보여주도록 고쳤습니다.
- 다만 이건 어디까지나 우회 방법입니다 — `/api/home`은 5개까지의 공지를 포함한 전체 카드 목록이라 상세 화면 진입마다 이 API를 다시 쓰는 건 낭비이고, 즐겨찾기 등록/해제 자체도 여전히 API가 없어 로컬에서만 토글됩니다. 이전 보고서에서 요청한 즐겨찾기 토글 API(`POST/DELETE /api/gyms/{id}/favorite` 등)가 있어야 제대로 해결됩니다.
